# KHALA

**조직의 업무 경험이 다음 AI 답변의 품질을 높이는 대화형 업무 플랫폼.** 신입은 AI와 문서·이미지를 보면서 일하고, 상사는 대화를 읽고 평가한다. LLM이 상사의 평가와 상사 본인의 업무 판단을 재사용 가능한 **검증 기준**으로 정리한다. 관련 기준을 다음 대화에 검색·적용하며 원문과 버전, 적용 이력을 보존한다.

`/chat`에서 멀티모달 AI 대화와 리뷰를 시작한다. 기존 PDF 검증은 `/`에서 계속 사용할 수 있다. [대화형 데모 가이드](docs/chat-test-guide.md)에 복사해서 쓸 질문·평가·기대 결과가 있다.

## 대화형 MVP 구조

- **실제 AI:** OpenAI Responses, Anthropic Messages, Gemini GenerateContent 또는 OpenAI 호환 HTTP API. 텍스트, PNG/JPEG 이미지, PDF, TXT/MD 입력을 실제 모델로 처리한다. 이미지 원본과 스캔 PDF 페이지는 시각 입력으로 전달한다. 응답은 완료 후 표시하며 스트리밍·음성·영상은 지원하지 않는다.
- **대화 UI:** MIT 오픈소스 assistant-ui의 외부 저장소 런타임·메시지·Markdown 렌더링에 KHALA의 파일 입력, 리뷰와 지식 UI를 연결했다. [오픈소스 안내](THIRD_PARTY_NOTICES.md).
- **영구 저장:** 기존 PostgreSQL 연결을 재사용한다. 대화, 메시지, 첨부파일, 리뷰, 현재 검증 기준과 불변 버전 이력을 별도 테이블에 저장한다. LLM 추론 중에는 DB 트랜잭션을 잡고 있지 않는다.
- **상사 리뷰:** 메시지를 우클릭하거나 **피드백 남기기**를 눌러 모달에서 평가한다. Esc 닫기, 초안 복원, Ctrl+Enter 저장을 지원한다. 추천·비추천은 상호 배타적이고 좋아요는 독립적이다. 평가를 DB에 저장하고 LLM이 앞뒤 맥락에서 검증 기준과 상황·판단·대응 사례를 자동 정리한다. 실패한 기준 추출은 재시도한다.
- **상사 본인의 대화:** 모든 원문을 저장한다. 상사가 명시한 재사용 가능한 업무 판단만 LLM이 정리해 기준으로 발행한다. 질문·추측·AI 답변은 상사의 판단으로 승격하지 않는다. 인용이 원문에 존재하는지 서버에서 확인한다.
- **사례 RAG:** 로컬 다국어 E5 임베딩의 의미 검색과 BM25 단어 검색을 RRF로 합친다. 업무·권한·버전 필터를 적용하고 기준 8개·사례 4개, 본문 10,000자 이내로 제한한다. LLM이 현재 상황에 맞는 내용을 판단하고 사용한 기준·사례를 답변에 표시한다. 임베딩은 내용 해시로 DB에 캐시하며 실패 시 단어 검색으로 대체했다고 표시한다. [RAG 구조와 설치](docs/rag-architecture.md).
- **모니터링:** 담당 구성원 대화를 5초마다 갱신한다. 새 메시지·리뷰 요청·미평가·보완 필요를 분리하고, 열람과 평가를 다른 상태로 기록한다. 대화 제목·요약·구성원·업무로 찾을 수 있다. KHALA 안의 대화가 대상이며 외부 ChatGPT 대화를 수집하지 않는다.
- **전문 지식 관리:** 상사의 최근 업무 발언 100개에 대해 원문·추출 상태·반영 버전을 확인하고 실패한 추출을 재시도한다. 원문 전체는 대화 목록에 계속 보존된다. 기준별 원문 출처·모든 버전·권한이 있는 대화의 최근 사용 100건을 조회한다. 중지된 기준은 새 검색에서 제외되고 기존 답변의 버전은 보존된다. 동시에 반영된 피드백을 오래된 LLM 응답이 덮어쓰지 못하도록 버전을 검사한다.
- **PDF 연결:** 이미 LLM이 정리한 PDF 리뷰 기준을 공통 기준 저장소에 가져와 대화에 재사용한다. PDF도 동일한 RAG를 통해 관련 기준 최대 6개와 유사 사례를 검색해 검증에 전달한다. 당시 기준 버전과 전달된 사례를 PDF 개정본에 고정한다. 사례가 현재 문서의 원문 근거를 대신하지 않으며 기존 필수 검증 승인 정책은 유지한다.

## 실행

```powershell
npm.cmd ci
npm.cmd run dev
```

브라우저에서 [http://127.0.0.1:3000](http://127.0.0.1:3000)을 연다. 기본 데이터는 `.khala/`의 내장 PostgreSQL에 저장된다. Next.js 서버를 한 번에 하나 실행한다. 외부 PostgreSQL을 쓰려면 `.env.local`에 `DATABASE_URL`을 지정한다.

최초 실행 전에 서버를 종료한 상태에서 `npm run admin:create`를 실행한다. 이름·이메일·비밀번호를 로컬 터미널에서 입력하면 최초 관리자 계정이 만들어진다. 비밀번호는 화면에 표시되지 않는다. 이후 서버를 실행하고 `/login`에서 로그인한다.

일반 사용자는 **회원가입 → 관리자 승인 → 로그인** 순서로 이용한다. 관리자는 `/admin`에서 역할(업무 사용자·리뷰어·관리자), 사용 상태, 담당 리뷰어를 지정한다. 업무 사용자는 담당 리뷰어 지정 후 승인할 수 있다. 대화와 PDF 원문은 작성자와 담당 리뷰어만 볼 수 있다. 관리자가 모든 원문을 열람하는 우회 권한은 없다. 이전 데모 사용자 소유 자료는 자동으로 새 계정에 배정하지 않는다.

`/settings`에서 제공업체·모델 ID·API 키를 저장하고 **연결 테스트**를 실행한다. 개인 설정 → 조직 기본 설정 → 서버 환경변수 순서로 적용된다. 조직 기본 설정은 관리자만 변경할 수 있다. 키는 AES-256-GCM으로 암호화해 DB에 저장하며 화면에 반환하지 않는다. ChatGPT 구독이나 Codex CLI는 사용하지 않는다. 대화·문서 검증·피드백 정리 모두 현재 요청자의 설정을 사용한다. 모델 ID는 직접 입력하며 이미지 입력과 구조화 출력 지원 여부는 선택한 모델에 달려 있다.

Ollama·LM Studio·vLLM 등은 **OpenAI 호환 · 로컬 LLM**을 선택한다. 로컬 주소는 브라우저 사용자의 PC가 아니라 **KHALA 서버 PC** 기준이다. 키가 없는 로컬 서버도 지원한다. 다른 사설 서버/프록시는 `KHALA_ALLOWED_API_ORIGINS`에 정확한 origin을 추가한다. 연결 실패 시 가짜 AI 응답으로 대체하지 않는다.

운영 환경 설정과 계정·모델 전체 테스트 순서는 [계정/API 설치 가이드](docs/account-model-guide.md)를 참고한다.

## 데모

1. 업무 사용자로 PDF를 선택하고 **PDF 검증 시작**을 누른다. LLM이 추출된 PDF 전체 텍스트와 업무별 검증 기준를 읽고, 주장·원문 근거·판정·수정 제안을 카드에 기록한다. 사람은 결과를 검토하고 필요한 경우 근거와 판정을 정정한다.
2. 미확인 항목이 있어도 **리뷰 요청**을 보낼 수 있다. 담당 리뷰어는 문제 카드의 **이 내용으로 수정 요청**에서 AI 지적·수정 방향·근거가 채워진 입력창을 열어 필요한 부분만 고친다. 기본 입력은 피드백 한 칸이며 근거는 펼쳐 수정할 수 있다. 초안은 같은 탭의 문서·개정본·페이지·사용자별로 유지되고 전송 성공 시 삭제된다. Ctrl+Enter 전송과 Esc 닫기를 지원한다.
3. 리뷰 피드백을 저장하면 LLM이 PDF 맥락과 기존 규칙 전체를 읽고 중복을 정리해 새 버전을 자동 발행한다. 상단 **수정본 업로드**에서 교체할 파일을 선택하고 확인하면 해당 피드백 버전으로 LLM이 다시 검증한다. 과거 검증 기록은 당시 버전으로 조회된다. AI 호출 실패 시 피드백은 저장되며 피드백 패널의 **AI 검증 기준 반영 다시 시도**로 재시도할 수 있다. 리뷰어 자신의 검증 경험도 문제 카드의 **이 경험을 검증 기준에 반영**에서 같은 경로로 반영한다.
4. 업로드 시 **시장조사 보고서** 또는 **일반 문서**를 선택한다. 각 업무의 검증 기준와 버전은 독립적으로 관리된다. 업무별 검증 기준에서 발행 버전과 변경 요약을 확인한다.
5. LLM이 페이지의 성장률 비교 여부를 해석해 비교 규칙과 성장률 카드를 적용한다. 서버는 인용문이 실제 페이지에 존재하는지와 선행 조건 충족 여부를 확인한다. 외부 출처 진위 확인·OCR·PDF 자체 수정은 지원하지 않는다. 검증 실패 시 파일은 유지되고 **AI 문서 검증 실행**으로 재시도한다. AI 검증 완료 전 최종 승인은 차단된다.

추출 텍스트가 페이지당 12,000자 또는 문서 전체 120,000자를 초과하거나 후보 검증 카드가 300개를 초과하면 검증을 보류하고 분할 업로드를 안내한다. PDF 업로드와 교체 시 자동 검증하며, 기존 문서는 명시적으로 재검증할 수 있다. 장시간 추론은 DB 트랜잭션 밖에서 수행하고 개정본 번호로 늦게 도착한 응답을 거절한다.

기존 로컬 방식으로 발행된 검증 기준는 과거 기록으로 유지한다. 해당 피드백에서 AI 정리를 다시 실행하면 다음 버전으로 발행하며, 그 뒤 수정 PDF를 등록한다. AI 정리에는 PDF에서 추출한 텍스트와 피드백이 선택한 API 모델로 전달된다.

## 검증

`python scripts/create-test-kit.py`로 PDF 테스트 파일과 가이드를 생성한다. 처음부터 전체 PDF 흐름을 따라가려면 [테스트 검증 기준](output/pdf/test-kit/START-HERE.html)를 연다. [전체 테스트 키트](output/pdf/khala-test-kit.zip)에는 PDF 7개, 단계별 HTML/Markdown 검증 기준, 피드백 복사용 JSON이 들어 있다. AI 응답 문구는 달라질 수 있으므로 검증 기준의 기대 동작을 기준으로 판단한다.

로컬 데모 데이터를 모두 지우려면 서버를 종료하고 `node scripts/reset-demo.mjs --confirm`을 실행한다. 문서·PDF 원본·판정·피드백·검증 기준 이력을 제거하고 기본 v1로 돌아간다. 샘플 파일·계정·API 설정은 유지한다.

```powershell
npm.cmd test
npm.cmd run build
```

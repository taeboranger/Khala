# KHALA 대화형 AI 테스트

먼저 [계정/API 설치 가이드](account-model-guide.md)대로 관리자와 테스트 계정을 만들고 API 연결 테스트를 통과한다. 아래 김지우·이서윤·박도현은 가입할 **테스트 계정 이름**이다. 관리자에서 김지우(업무 사용자)의 담당 리뷰어를 이서윤으로, 이서윤(리뷰어)의 담당 리뷰어를 박도현으로 지정한다. 사용자 선택기 대신 로그아웃·로그인으로 전환한다. 동시 테스트는 별도 브라우저 프로필/시크릿 창을 사용한다. 같은 브라우저 탭끼리는 로그인 쿠키가 공유된다.

`/chat`에서 업무를 선택하고 시작한다. 대화와 기준 정리는 설정한 API 모델을 실제 호출하므로 답변 표현은 달라질 수 있다. 이미지 파일이 없다면 아래 HTML을 `chart.svg`로 저장 후 브라우저에서 캡처한 PNG를 첨부해도 된다: `<svg xmlns="http://www.w3.org/2000/svg" width="600" height="240"><rect width="600" height="240" fill="white"/><text x="30" y="70" font-size="28">Revenue: 2024 = 120</text><text x="30" y="140" font-size="28">Revenue: 2025 = 180</text><text x="30" y="200" font-size="20">Same market, same currency</text></svg>`.

## 1. 신입이 파일을 보면서 AI와 일하기

**김지우 · 업무 사용자**로 로그인하고 업무를 **시장조사 보고서**로 선택하고 **새 대화**를 누른다. `tmp/chat-verification/synthetic-chart.png`를 끌어 놓고 아래 문장을 보낸다.

> 이미지의 2024년과 2025년 매출을 읽고 증가율을 계산해 줘. 보고서에 넣을 문장도 써 줘.

이미지에는 동일 시장 매출 120과 180이 표시되어 있다. 모델이 이미지를 직접 읽고 50%를 계산하는지 확인한다. 질문을 이어 보내면 앞선 대화를 이어받는다. 새로고침 후 왼쪽 대화 목록에서 원문과 첨부파일을 다시 확인할 수 있다.

PDF도 첨부할 수 있다. 짧은 테스트용 PDF를 첨부한 뒤 “이 문서의 주장과 출처를 대조해 줘”라고 요청한다. 텍스트 PDF는 페이지 번호와 함께 전달하며, 텍스트가 거의 없는 스캔 페이지는 이미지로 전달한다. 현재 파일은 한 번에 4개, 각 10MB까지 지원한다. 스캔 페이지는 PDF당 4쪽까지다. 음성·영상 입력은 이번 구현에 포함되지 않는다.

## 2. 상사가 신입 대화를 평가하고 기준으로 남기기

김지우의 대화 상단에서 **리뷰 요청**을 누른다. **이서윤 · 리뷰어**로 로그인하고 **대화 모니터링**에서 방금 대화를 선택한다. AI 답변을 **우클릭**하거나 **피드백 남기기**를 누른다. 모달에서 아래 의견을 입력하고 **보완 필요 → 평가 저장 · 기준 자동 정리**를 누른다. Esc로 닫아도 입력 초안이 유지되며 Ctrl+Enter로 저장할 수 있다.

> 시장조사에서 성장률을 계산할 때는 두 수치의 시장 범위, 대상 지역, 기간, 지표 정의와 단위를 먼저 비교해야 합니다. 범위가 다르면 바로 성장률을 계산하지 말고, 동일 기준의 자료를 요청하세요.

평가 원문이 즉시 DB에 저장되고, LLM이 대화 맥락과 기존 기준을 참고해 공통으로 재사용할 판단을 정리한다. 성공하면 **검증 기준 N개 반영**이 보인다. 왼쪽 **검증 기준**에서 정리된 기준, 확인 방법, 버전, 상사 원문 인용을 확인한다. “좋아요”처럼 재사용할 판단이 없는 의견은 리뷰로만 저장될 수 있다.

## 3. 새 대화에서 그 경험이 실제로 쓰이는지 확인

**김지우**로 돌아와 **시장조사 보고서** 새 대화를 만들고 보낸다.

> 국내 온라인 시장 매출 100에서 글로벌 온오프라인 시장 거래액 150으로 늘었으니 성장률 50%라고 써도 될까?

답변은 범위와 지표가 다르므로 직접 비교할 수 없다고 설명해야 한다. 답변 아래 **적용된 검증 기준**을 펼쳐 이전 리뷰에서 만들어진 기준 제목과 버전을 확인한다. 모델은 업무 종류와 검색 관련성으로 추린 후보 중 이번 질문에 맞는 기준만 사용한다. 관련 기준이 없는 답변에는 적용 표시가 없다.

## 4. 상사 본인의 업무 대화도 기준으로 남기기

**이서윤**으로 로그인하고 업무를 **일반 문서**로 바꾼 뒤 새 대화에서 보낸다.

> 내 업무 원칙을 정리해 줘. 설문조사 보고서에서 응답률은 유효 응답자 수를 전체 발송 대상자 수로 나눠 계산해야 합니다. 응답자 중 특정 답변 비율과 전체 응답률을 혼동하지 마세요.

답변 아래 **상사의 업무 판단에서 검증 기준 N개를 반영했어요**가 나타나는지 확인한다. 검증 기준 목록에서 일반 문서로 필터링하면 해당 판단과 원문 근거가 나온다. 상사의 질문이나 AI가 생성한 답변 자체를 상사의 전문 판단으로 간주하지 않는다. 전체 대화 원문은 추출 여부와 관계없이 저장된다. 이서윤의 대화는 **박도현**이 담당 리뷰어로 볼 수 있다.

## 장애·데이터 보존

모델 실패 시 이미 저장된 질문과 첨부파일은 남으며 **답변 다시 받기**로 재시도한다. 리뷰의 기준 추출이 실패하면 리뷰 원문은 남고 **기준 정리 다시 시도**가 표시된다. 입력 중인 메시지와 리뷰 초안은 동일 브라우저 탭의 세션에 보존한다. 아직 보내지 않은 첨부파일은 새로고침하면 다시 선택해야 한다.

선택적으로 `node scripts/check-chat-live.mjs`를 실행하면 결과가 `tmp/chat-verification/live-result.json`에 기록된다. 스크립트는 `LLM_*` 환경변수 설정이 필요하며 실제 API 사용량이 발생한다. 자동 실제 모델 테스트는 격리된 메모리 DB를 사용했으므로 그 테스트 대화가 앱의 실제 대화 목록에 나타나지 않는 것이 정상이다.

## 5. 모니터링과 지식 이력 확인

별도 브라우저 프로필 두 개에서 각각 김지우와 이서윤으로 로그인한다. 이서윤의 **대화 모니터링**을 열어 두고 김지우 탭에서 새 대화를 시작하거나 메시지를 보낸다. 5초 내 자동 갱신으로 대화가 나타나고 **새 메시지**, **미평가 대화** 수가 바뀐다. 리뷰 요청을 보내면 **리뷰 요청**으로 필터링할 수 있다. 대화를 열어 읽으면 새 메시지 표시는 해제되지만, 미평가 상태는 리뷰를 남기기 전까지 유지된다. 평가 후 김지우가 추가 질문을 보내면 다시 미평가로 구분된다.

이서윤의 **내 전문 지식 기록**에서 4단계 발언 원문과 **기준 반영** 상태를 확인한다. 아직 추출하지 못한 발언은 **미처리 · 실패** 필터로 찾아 재시도할 수 있다. **검증 기준 → 근거·버전·적용 이력**을 열면 상사의 원문 인용, 버전별 내용, 그 기준이 실제 사용된 대화를 확인하고 원문으로 이동할 수 있다. **앞으로의 검색에서 제외**를 누르면 새 답변에서는 해당 기준을 검색하지 않으며, 과거 답변은 당시 버전으로 남는다.


현재 서비스는 단일 조직을 위한 계정·승인·담당 리뷰어 권한을 제공한다. 여러 조직의 데이터를 분리하는 멀티테넌트 기능은 포함하지 않는다. 검색은 로컬 다국어 임베딩과 BM25를 함께 사용하고 LLM이 실제 적용 기준·사례를 판단한다. [RAG 구현 문서](rag-architecture.md)에 저장·선택·권한·장애 처리를 설명했다.

## 6. 빠른 평가와 유사 사례 RAG

상사가 신입의 대화를 열면 질문과 답변 아래에 **추천 · 비추천 · 좋아요**가 보인다. 추천 후 비추천을 누르면 추천은 해제된다. 좋아요는 별도로 켜고 끌 수 있다. 다시 누르면 취소되며 새로고침 후에도 평가가 보존된다. 빠른 평가는 별도 LLM 호출 없이 저장되며 리뷰 완료 처리나 검증 규칙 자동 발행을 의미하지 않는다.

2단계의 구체적인 피드백을 남긴 뒤 새 대화에서 3단계 질문을 보낸다. 답변 아래 **조직 경험 검색 · 의미 + 단어**와 **참고한 유사 사례**를 확인한다. 사례에는 상황·판단·대응이 표시되고, 원문 접근 권한이 있으면 **원래 대화 보기**로 이동할 수 있다. 사례가 조건에 맞지 않으면 LLM은 사용하지 않으며, 그 경우 참고 사례 표시가 없어도 정상이다.

비추천 사례가 검색되면 피해야 할 예시로 다뤄야 하며 그대로 정답처럼 복사하면 안 된다. 추천·좋아요는 사실 검증이 아닌 선호 신호다. 권한 없는 대화 원문은 검색되지 않는다. 새로 정리된 공통 사례는 개인 식별 내용을 제외한 요약으로 공유한다. 사용 중지되거나 수정된 기준에 연결된 이전 사례는 새 검색에서 제외하고 과거 답변 기록은 그대로 보존한다.

처음 해당 기준·사례를 검색하면 로컬 벡터를 생성하므로 잠시 시간이 더 걸릴 수 있다. 같은 자료는 DB 캐시를 사용한다. 모델 실행 실패 시 **단어 검색**으로 표시하며 의미 검색이 성공한 것처럼 표시하지 않는다.

# 계정과 API 모델 연결

## 1. 처음 시작하기

```powershell
npm ci
# 실행 중인 KHALA 서버를 먼저 종료한다. 최초 한 번만 실행한다.
npm run admin:create
npm run dev
```

관리자 생성 명령에서 이름·이메일·12자 이상 비밀번호를 입력한다. 비밀번호는 화면이나 명령행 인수에 표시되지 않는다. 이미 관리자가 있으면 다시 만들지 않는다. `.env.local`도 이 명령에서 읽는다. 내장 PGlite DB는 서버와 관리 명령이 동시에 열지 않도록 한다.

[로그인](http://127.0.0.1:3000/login)에서 관리자로 로그인한다. **모델 설정 → 조직 기본 모델**을 저장하고 **연결 테스트**로 실제 응답을 확인한다. 연결 테스트는 짧은 유료 API 호출이 될 수 있다. 자동으로 과금 호출을 실행하지 않는다.

## 2. 가입과 승인

1. 별도 브라우저 프로필에서 **회원가입**으로 작성자와 리뷰어 계정을 신청한다.
2. 승인 전 로그인하면 **관리자 승인 대기 중**으로 차단되어야 한다.
3. 관리자는 **계정 관리**에서 상사의 역할을 **리뷰어**, 상태를 **사용 중**으로 저장한다.
4. 작성자의 역할은 **업무 사용자**, 담당 리뷰어는 방금 승인한 상사, 상태는 **사용 중**으로 저장한다.
5. 작성자가 로그인하면 자신의 대화를 시작할 수 있다. 담당 상사는 **대화 모니터링**에서 확인한다.

관리자도 직접 AI 업무를 할 수 있으며 전문가 발언을 기준으로 추출한다. 관리자·리뷰어 본인 작업을 다른 리뷰어에게 검토받으려면 담당 리뷰어를 지정한다. 직접 만든 작업은 항상 본인에게 보인다. 담당 리뷰어가 없으면 타인의 리뷰를 받을 수 없으므로 필요할 때 관리자가 배정한다.

사용 중지·역할·담당 리뷰어 변경 시 해당 계정의 기존 세션을 폐기한다. 다시 로그인해야 하며 이미 열린 화면의 다음 API 요청부터 차단된다. 마지막 활성 관리자를 없애거나 담당 구성원이 있는 리뷰어를 바로 중지할 수 없다. 구성원을 먼저 재배정한다. 이메일 인증·비밀번호 재설정·MFA·다중 조직 분리는 이번 범위에 포함되지 않는다.

## 3. 모델 설정

| 선택 | 연결 방식 | 필요한 설정 |
| --- | --- | --- |
| OpenAI | Responses API | API 키, 모델 ID |
| Anthropic Claude | Messages API + 구조화 출력 | API 키, 해당 기능을 지원하는 모델 ID |
| Google Gemini | GenerateContent API + JSON Schema | API 키, 모델 ID |
| OpenAI 호환 | Chat Completions API | 기본 주소, 모델 ID, 필요 시 키 |

호환 서버 프리셋으로 xAI, DeepSeek, Mistral, Groq, Together, OpenRouter, Ollama, LM Studio, vLLM 주소를 제공한다. 서버·모델에 따라 **JSON Schema / JSON 모드 / 프롬프트로 JSON 요청**을 선택한다. 호환 프리셋이 모든 모델의 기능을 보장하는 것은 아니다. 모델이 반환한 JSON은 서버에서 다시 검증하며 실패하면 오류와 재시도 경로를 표시한다.

개인 설정이 있으면 그것을 사용하고, 없으면 조직 기본, 그마저 없으면 `LLM_*` 환경변수를 사용한다. **내 설정 지우고 기본 모델 사용**으로 조직 설정을 다시 따른다. 대화와 피드백 정리는 요청자의 모델 설정을 사용한다. 리뷰어가 남긴 피드백의 정리는 리뷰어 설정으로 실행된다.

API 키는 브라우저에 저장하지 않으며 서버의 DB에는 암호문만 저장한다. 저장 후 화면에 키를 돌려주지 않는다. 같은 제공업체·서버에서 키 입력을 비워 두면 기존 키를 유지한다. 다른 제공업체·서버로 바꾸면 키를 다시 입력해야 한다. 로컬 서버는 키 없이도 저장할 수 있다.

로컬 주소는 **KHALA 서버 컴퓨터 기준**이다. 서버가 Docker 안에 있다면 `127.0.0.1`은 컨테이너 자체다. 호스트 모델 서버를 쓰려면 도달 가능한 주소를 사용하고 해당 origin을 `KHALA_ALLOWED_API_ORIGINS`에 추가한다. 예: `http://host.docker.internal:11434`. 리다이렉트를 따라 키를 전달하지 않는다.

텍스트·PDF·이미지 입력을 유지한다. 이미지와 스캔 PDF 대화에는 이미지 입력을 지원하는 모델이 필요하다. ChatGPT 구독·Codex CLI는 모델 실행에 사용하지 않는다.

## 4. 운영 설정과 백업

`.env.example`을 참고해 `.env.local`을 작성한다. 키 파일과 `.env.local`은 Git에서 제외된다.

- `APP_ORIGIN`: 실제 접속 origin, 예: `https://khala.example.com`. 변경 요청의 Origin을 확인한다.
- `SESSION_COOKIE_SECURE`: 프로덕션 기본 true. HTTPS로 서비스한다. 로컬 HTTP에서 `npm start`를 시험할 때만 false로 지정한다.
- `KHALA_ENCRYPTION_KEY`: **32바이트 난수의 Base64**. 외부 PostgreSQL 사용 시 필수이며 모든 서버 인스턴스가 같은 키를 사용해야 한다. 안전한 비밀 관리 도구에서 생성·보관한다.
- 내장 DB에서는 `.khala/api-key.key`를 자동 생성한다. DB와 함께 백업하되 접근 권한을 제한한다. 이 파일을 잃으면 저장된 API 키를 복호화할 수 없다. 키를 변경할 때는 기존 키로 복호화·재암호화하는 별도 이전이 필요하다.
- `KHALA_DATA_DIR`: 내장 DB와 로컬 암호화 키의 저장 디렉터리. 기본 `.khala`. 격리 테스트에서는 `tmp/` 아래 별도 경로를 쓴다.
- `KHALA_ALLOWED_API_ORIGINS`: 추가 API 서버의 origin 목록. 쉼표로 구분한다. 경로와 API 키는 넣지 않는다.

이 구현은 한 조직의 공유 검증 기준을 축적하는 서비스다. 원문 대화·파일은 작성자/담당 리뷰어로 제한하고, LLM이 정리한 공통 기준·사례는 조직에서 재사용한다. 여러 회사가 한 DB를 공유하는 멀티테넌트 배포용 구분은 없다. 계정 관리 권한이 곧 모든 대화 열람 권한은 아니다.

## 5. 전체 테스트 흐름

계정은 김지우(작성자), 이서윤(리뷰어), 박도현(리뷰어)을 예로 든다. 김지우→이서윤, 이서윤→박도현으로 배정한다. 역할을 바꾸는 데모 선택기는 없으며 계정별 브라우저 프로필 또는 로그아웃·로그인으로 전환한다.

1. **가입·승인:** 위 2절대로 로그인 차단과 승인 후 접속을 확인한다.
2. **API 연결:** 관리자 조직 기본 설정 → 연결 테스트. 작성자 설정 화면에서 **조직 기본 모델**이 현재 적용으로 보이는지 확인한다.
3. **AI 대화:** 작성자가 시장조사 대화를 시작하고 “국내 온라인 매출 100과 글로벌 전체 거래액 150을 비교해 성장률 50%라고 써도 될까?”라고 묻는다.
4. **리뷰:** 이서윤이 모니터링에서 열어 추천·비추천·좋아요, 우클릭 피드백을 남긴다. “두 자료의 범위와 지표가 같을 때만 성장률을 계산하세요”라고 구체적으로 평가한다.
5. **축적·재사용:** 검증 기준의 원문·버전을 확인하고 새 대화에서 비슷한 요청을 보낸다. 적용 기준·관련 사례 표시를 확인한다. 상세 문구와 범위는 [대화 테스트 가이드](chat-test-guide.md)에 있다.
6. **상사의 작업:** 상사가 “설문 응답률은 유효 응답자 수/전체 발송 대상자 수로 계산해야 한다”라고 직접 판단을 말한다. 전문 지식 기록에 원문·추출 상태가 보이는지 확인한다.
7. **PDF 첨부:** 새 대화에 PDF를 첨부하고 주요 주장과 페이지 근거를 정리해 달라고 요청한다. 스캔 문서를 시험하려면 이미지 입력이 가능한 모델을 사용한다.
8. **개인 설정:** 작성자 개인 모델을 저장하고 새 답변의 모델이 바뀌는지 확인한다. 삭제하면 조직 기본으로 돌아와야 한다.
9. **권한:** 담당하지 않는 사용자는 해당 대화·첨부를 열 수 없고, 업무 사용자는 계정 관리·조직 모델 변경 API를 사용할 수 없어야 한다. 관리자가 계정을 중지하면 기존 쿠키도 사용할 수 없어야 한다.

`npm test`는 API 계약 모의 응답·암호화·권한·기존 업무 흐름을 검사한다. `npm run build` 후 `node scripts/check-account-flow.mjs`는 별도 DB와 모의 LLM HTTP 서버로 실제 회원가입→승인→대화를 브라우저에서 한 번 확인한다. Playwright를 별도로 설치하거나 `PLAYWRIGHT_MODULE`로 설치 경로를 지정하고 필요하면 `PLAYWRIGHT_CHANNEL=msedge`를 지정한다. 기존 DB에는 쓰지 않으며 테스트 데이터는 `tmp/account-smoke-*`에 남는다. 실제 제공업체 키의 유효성과 선택한 모델 지원 여부는 설정 화면의 연결 테스트로 확인한다.

`node scripts/reset-demo.mjs --confirm`은 서버를 종료한 뒤 기본 로컬 DB의 채팅 업무 자료를 초기화하는 명령이다. 계정·로그인·모델 설정은 유지한다. 외부 DB나 사용자 지정 데이터 디렉터리에는 이 초기화 명령을 사용하지 않는다.
